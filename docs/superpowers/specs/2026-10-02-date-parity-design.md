# Calendar and DatePicker parity

Continuation of the approved parity roadmap in docs/remaining-contracts.md and the producer docs/parity-form-controls-plan.md. Work inline in the existing linked checkouts as in the preceding batches; no commit or push requested.

Provide a compact single Gregorian date Calendar and DatePicker matching the pinned Base Nova month appearance. Both share a new adapter-required date-grid primitive: native date input proxy, optional label, button trigger/value/icon, calendar popup/header/previous/caption/next, semantic table grid, weekday/week/cell/day prototypes. Prototypes give repeated elements the same typed classes/styles/unstyled contract as every other part. The local interaction helper creates rows from these prototypes; no DayPicker, Base UI, Radix or date-fns implementation dependency.

Calendar renders the grid inline. DatePicker renders it in a native auto popover with shared collision positioning, focus on its selected/first enabled day, Escape restoration and selection dismissal. NativeDatePicker retains date-field and browser presentation. ISO YYYY-MM-DD strings preserve date-only semantics without timezone conversion. Optional value, name, disabled, required, min/max, locale (BCP47; Gregorian formatting), firstDayOfWeek (0–6), defaultMonth (YYYY-MM), placeholder and control ARIA fields. IDs are supplied by caller (id and popupId), as for Select. Locale changes presentation only; firstDayOfWeek defaults to Sunday and is explicit. Month navigation clamps to valid day counts; arrows are direction aware, Home/End target the displayed week, PageUp/Down change month, Shift+PageUp/Down change year. Focus movement never commits a date; Enter/Space do. Native input/change/model events, required validation, disabled fieldsets, inert, form reset, external model updates and reactive recipe overrides must work. One roving day tab stop. Today, outside-month, selected, disabled, focus and invalid states are token styled; forced colors remain legible.

Scope: one month, one selection, min/max bounds; no date ranges, time picking, alternative calendar systems, predicates, month/year dropdowns or controlled open prop. Preview isolated neutral tokens in the real Nuxt Vapor dashboard, light/dark, RTL, locale, required/reset, bounds and overrides. Check all three browser engines, strict typed consumers, standalone/library generation and Nuxt production build. Keep generated files reproducible from producer and plugin changes.
